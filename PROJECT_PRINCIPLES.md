# PaperOS Project Principles

These principles are the foundation of PaperOS.

Every design decision, architectural change and feature proposal should be evaluated against them.

If a proposal violates these principles, the principles take precedence.

---

## 1. Thought Comes First

PaperOS exists to help people think.

Everything else is secondary.

---

## 2. Documents Before Applications

Documents are permanent.

Applications are tools.

The system is organized around knowledge, not software.

---

## 3. Calm Before Convenience

Avoid interruptions.

Avoid unnecessary urgency.

Respect the user's attention.

---

## 4. Keyboard First

Every essential function must be usable from the keyboard.

Other input methods complement the experience but never replace it.

---

## 5. Open Formats

Knowledge should outlive software.

Whenever practical, use open, documented and human-readable formats.

---

## 6. Hardware Independence

PaperOS belongs to no single device.

The architecture must allow multiple implementations without changing the philosophy.

---

## 7. Simplicity Before Features

Every new feature has a permanent maintenance cost.

Add only what genuinely improves the experience.

---

## 8. Learn From History

Study the best ideas from computing history.

Preserve enduring concepts rather than chasing novelty.

---

## 9. Stability Builds Trust

Users should be able to rely on PaperOS for years.

Compatibility and predictability are features.

---

## 10. Respect the User

The computer serves its user.

Never the opposite.

No manipulation.

No unnecessary complexity.

No artificial dependency.

---

## The PaperOS Question

Before writing code, designing an interface or proposing a new feature, ask:

**Does this help people think?**

If the answer is yes, continue.

If the answer is no, reconsider.

---

*"The purpose of PaperOS is not to demand attention.*

*Its purpose is to quietly accompany thought."*
